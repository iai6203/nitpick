# 테스트 목록: nitpick.nvim v1 (승인됨)

## 요구사항 출처
- 대화 결정: Claude Code와의 연동은 빼고 Neovim 안에서만 리뷰한 뒤 클립보드로 복사한다. 이름은 `nitpick.nvim`, 형식은 plannotator(`backnotprop/plannotator@87dcec4`의 `packages/ui/utils/parser.ts`)를 따른다.
- 여러 파일을 넘나들며 리뷰하고, 별도 모드 없이 평소 상태 그대로 쓴다.
- 줄 번호는 원본의 블록 단위가 아니라 선택한 실제 줄 범위를 쓴다.

## 사례

### A. 피드백 직렬화 (제안: `nitpick.export`) — 순수 함수, 단위 테스트

**파일 리뷰 — 파일이 하나여도 항상 묶음 형식**
1. [정상·확정] 코멘트가 있는 파일이 하나면 `# File Feedback` 머리말, 안내 문장, `## <path>`, `I've reviewed this document and have N pieces of feedback:` 순서로 출력한다.
   - 근거: `BUNDLE_DOC_EXPORT_HEADING`, `exportLinkedDocAnnotations`
2. [정상·확정] 한 줄 코멘트는 `### 1. (line 12) Feedback on: "<원문>"` 다음 줄에 `> <코멘트>`로 출력한다.
3. [정상·확정] 여러 줄 코멘트의 줄 라벨은 `(lines 20–24)`로 출력한다 (en dash).
4. [정상·확정] 삭제 표시는 `Remove this`, 원문 펜스, `> I don't want this in the document.` 순서로 출력한다.
5. [정상·확정] 파일 전체 코멘트는 줄 라벨 없이 `General feedback about the document`로 출력한다.
6. [경계·확정] 어노테이션이 1개면 `1 piece`, 2개 이상이면 `N pieces`로 쓴다.
7. [정상·확정] 한 파일 안에서는 시작 줄, 시작 열 순서로 정렬하고 1부터 번호를 매긴다. 파일 전체 코멘트의 정렬 위치는 원본 `sortAnnotationsInDocumentOrder`를 따른다.
8. [정상·확정] 여러 파일은 파일마다 `## <path>` 섹션으로 나누고, 번호는 파일마다 1부터 다시 시작한다.
9. [정상·확정] 파일 섹션은 처음 어노테이션을 단 순서대로 출력한다.
10. [경계·확정] 어노테이션이 없는 파일은 섹션을 만들지 않는다.
11. [정상·확정] 전체 출력은 `---\n`으로 끝난다.
12. [경계·확정] 코멘트가 여러 줄이면 원본처럼 첫 줄에만 `> `를 붙인다.

**메시지 리뷰**
13. [정상·확정] 메시지 버퍼의 피드백은 `# Message Feedback` → 안내 문장 → `## Message 1` → `Message excerpt:` + markdown 펜스 → `# Feedback for Message 1` 순서로 출력하고, 주체(subject)는 `message`를 쓴다.
14. [경계·확정] 1200자를 넘는 메시지는 발췌문을 1200자에서 자르고 `...`을 붙인다.
15. [경계·확정] 본문에 ```` ``` ````가 있으면 그보다 긴 펜스로 감싼다.

### B. 리뷰 상태 (제안: `nitpick.review`)
16. [정상·확정] 서로 다른 파일 버퍼에 단 어노테이션이 하나의 리뷰에 모인다.
17. [정상·확정] 커서 위치의 어노테이션을 지우면 그 하나만 사라진다.
18. [정상·확정] 커서 위치의 어노테이션 코멘트를 수정하면 수정된 내용으로 출력된다.
19. [정상·확정] 리뷰를 초기화하면 모든 어노테이션과 표시가 사라진다.
21. [실패·확정] 파일도 메시지 버퍼도 아닌 이름 없는 버퍼에서는 어노테이션을 추가하지 않고 알림을 띄운다.
22. [정상·확정] 경로는 Neovim cwd 기준 상대 경로로 쓰고, cwd 밖의 파일이면 절대 경로로 쓴다.

### C. 위치 추적 — 헤드리스 Neovim 통합 테스트
23. [정상·확정] 어노테이션 위쪽에 줄을 추가하면 출력되는 줄 번호가 그만큼 밀린다.
24. [정상·확정] 원문(`originalText`)은 어노테이션을 만든 시점의 텍스트를 유지한다.
25. [경계·확정] 대상 범위가 통째로 지워져도 어노테이션은 남고, 현재 extmark 위치를 줄 번호로 쓴다.
27. [상태·확정] 버퍼를 닫았다가(`:bdelete`) 다시 열어도 어노테이션이 남아 있다.

### D. 복사 (제안: `nitpick.copy`)
28. [정상·확정] 복사하면 A의 출력이 `+` 레지스터에 들어간다.
29. [실패·확정] 클립보드 provider가 없으면 unnamed 레지스터(`"`)에 넣고 설정이 필요하다고 알린다.
30. [경계·확정] 어노테이션이 0개면 복사하지 않고 "리뷰 내용이 없습니다" 알림만 띄운다. 레지스터는 바뀌지 않는다.
20. [상태·확정] 복사한 뒤에도 어노테이션은 그대로 남는다. (B에서 옮김: 복사 기능이 필요)
26. [상태·확정] 저장하지 않은 변경이 있는 파일이 포함되어 있어도 복사는 하되 경고를 띄운다. (C에서 옮김: 복사 기능이 필요)
35. [정상·확정] 클립보드에 복사하면 정보 수준(INFO)의 성공 알림을 띄운다. (D RED 검토 중 결정)

### E. 평소 편집 상태 보존
31. [회귀·확정] `setup()`은 어떤 키맵도 만들지 않는다.
32. [정상·확정] 모든 기능은 `:Nitpick <sub>` 명령으로 쓸 수 있고, 어느 버퍼에서든 별도 모드 없이 동작한다.
33. [정상·확정] visual 범위에서 `:'<,'>Nitpick comment` / `delete`를 실행하면 그 범위를 대상으로 한다.
36. [정상·확정] 코멘트 내용 없이 `:Nitpick comment` / `global`을 실행하면 `vim.ui.input`으로 입력받은 내용으로 코멘트를 단다. (E RED 검토 중 결정)
37. [실패·확정] 입력을 취소하거나(nil) 빈 내용을 입력하면 어노테이션을 추가하지 않는다.
38. [정상·제안] 내용 없이 `:Nitpick edit`을 실행하면 입력창에 기존 코멘트가 미리 채워지고, 입력한 내용으로 바뀐다.

### F. 메시지 버퍼
34. [정상·확정] `:Nitpick paste`는 `ft=markdown`인 `nofile` 스크래치 버퍼를 열고, 그 버퍼를 메시지 리뷰(13)로 취급한다.

### G. 표시 — 하이라이트와 가상 줄(virt_lines)
39. [정상·확정] 코멘트 범위에 하이라이트 그룹 `NitpickComment`가 적용된다.
40. [정상·확정] 삭제 표시 범위에 하이라이트 그룹 `NitpickDelete`가 적용된다.
41. [정상·확정] 코멘트 범위의 끝 줄 아래에 코멘트 본문이 가상 줄로 `  ↳ 내용` 모양으로 보인다(하이라이트 `NitpickCommentText`). 코멘트가 여러 줄이면 줄마다 가상 줄이 하나씩 생긴다.
42. [정상·확정] 코멘트를 수정하면 가상 줄의 내용도 바뀐다.
43. [정상·확정] 어노테이션을 지우면 하이라이트와 가상 줄이 함께 사라진다.
44. [상태·확정] 버퍼를 닫았다가 다시 열면 하이라이트와 가상 줄도 복원된다.
45. [정상·확정] 파일 전체 코멘트는 버퍼 첫 줄 위에 가상 줄 `  ↳ [전체] 내용`으로 보인다.
45-1. [정상·확정] 파일 전체 코멘트를 달면, 그 파일을 첫 줄부터 보여 주는 창은 가상 줄이 보이도록 위로 스크롤된다(`topfill`). (G GREEN 화면 확인 중 추가)
45-2. [상태·확정] 파일 전체 코멘트가 있는 파일을 창에 다시 띄우거나 닫았다가 다시 열면, 첫 줄부터 보여 주는 창에서 가상 줄이 보인다.
46. [정상·확정] 하이라이트 그룹은 `default = true`로 정의해 사용자가 정한 색을 덮어쓰지 않는다. 사용자 정의가 없으면 `NitpickComment`는 `DiagnosticUnderlineInfo`, `NitpickCommentText`는 `Comment`에 연결되고 `NitpickDelete`는 취소선이다.
- signcolumn 번호 표시는 하지 않는다.

### H. 겹친 어노테이션 고르기 (변경, 제안: `annotations_at_cursor`)
문제: 커서 위치의 어노테이션을 찾을 때(`find_at_cursor`) 커서 줄만 보고 처음 추가된 후보 하나만 돌려줘서, 비슷한 위치에 단 어노테이션 중 원하는 것을 지우거나 고칠 수 없다.

**후보 찾기**
47. [정상·신규·확정] 커서 줄을 범위에 포함하는 어노테이션이 여러 개면 모두 후보로 돌려준다.
48. [정상·신규·확정] 커서 열까지 범위 안에 드는 후보를 줄만 겹치는 후보보다 앞에 둔다.
49. [정상·신규·확정] 커서 열 조건이 같으면 범위가 좁은 후보를 앞에 둔다. 줄 수를 먼저, 같으면 글자 수를 비교한다.
50. [경계·신규·확정] 범위가 완전히 같으면 나중에 단 후보를 앞에 둔다.
51. [정상·신규·확정] 파일 전체 코멘트(global)는 커서가 첫 줄에 있을 때만 후보에 넣는다.
51-1. [정상·신규·제안] global 후보는 범위 후보들의 뒤에 둔다.
52. [경계·신규·제안] 다른 버퍼의 어노테이션은 후보에 넣지 않는다.

**`:Nitpick remove`**
53. [정상·유지] 후보가 하나면 고르는 창 없이 바로 지운다. (보강: `vim.ui.select`를 호출하지 않는다)
54. [정상·신규·확정] 후보가 둘 이상이면 `vim.ui.select`로 정렬 순서대로 보여 주고, 고른 어노테이션만 지운다.
55. [정상·신규·제안] 고르는 창의 항목은 `L3 comment: 내용`, `L1–5 comment: 내용`, `L2 deletion: "원문"`, `[전체] 내용` 모양이다. 여러 줄인 내용은 첫 줄만 보여 준다.
56. [실패·신규·제안] 고르는 창에서 취소하면 아무것도 지우지 않는다.
57. [실패·신규·제안] 후보가 없으면 `nitpick: 커서 위치에 어노테이션이 없습니다.` 경고(WARN)를 띄운다.
57-1. [정상·신규·확정] 커서가 첫 줄에 있으면 `:Nitpick remove`로 파일 전체 코멘트를 지울 수 있다.

**`:Nitpick edit`**
58. [정상·신규·제안] 수정 후보에는 코멘트가 있는 어노테이션(comment, global)만 넣고 삭제 표시는 넣지 않는다.
59. [정상·유지] 후보가 하나면 바로 수정하고, 내용 없이 실행하면 입력창에 기존 코멘트가 채워진다. (사례 38)
60. [정상·신규·확정] 후보가 둘 이상이면 먼저 고르고, 고른 코멘트를 기본값으로 입력창을 연 뒤 그 코멘트만 바꾼다.
60-1. [정상·신규·확정] 후보가 여럿이라 고른 뒤 입력창이 자기 창을 열면, 포커스는 그 입력창에 있다. (버그 수정: 고른 뒤의 처리를 `nvim_buf_call`로 감싸서 포커스가 편집 창으로 돌아갔다)
61. [실패·신규·제안] 고르는 창이나 입력창에서 취소하면 아무것도 바꾸지 않는다.
62. [실패·유지] 수정 후보가 없으면 `nitpick: 커서 위치에 코멘트가 없습니다.` 경고를 띄운다. (공백이던 동작을 고정)

**review 모듈의 기존 함수**
63. [정상·유지·확정] `remove_at_cursor`, `edit_at_cursor`, `text_at_cursor`는 남기고, 후보가 하나일 때 지금처럼 동작한다. (사례 17·18·42·43)
64. [정상·신규·확정] 후보가 여럿이면 세 함수는 정렬된 첫 번째 후보에 동작한다. 고르는 창은 명령(`nitpick.command`)이 띄운다.

### I~M. 라벨 (변경, 원본의 quick label)
요구사항: 라벨은 미리 정해 둔 코멘트다. 기본 라벨은 코드에 두고 README에도 같은 목록을 보여 주며, 사용자가 `labels`를 지정하면 기본 목록 전체를 대체한다. 라벨에는 코멘트를 덧붙이지 않고(같은 위치에 comment를 따로 단다), 고칠 수 없으며 추가·삭제만 한다. 기본 목록은 원본의 quick label 10개 뒤에 👍 Looks good을 더한다.
형식 원본: `backnotprop/plannotator@87dcec4`의 `packages/ui/utils/quickLabels.ts`(`DEFAULT_QUICK_LABELS`, `THUMBS_UP_LABEL`)와 `packages/ui/utils/parser.ts`(`renderAnnotationEntries`, `labelSummaryBlock`). 라벨 어노테이션의 본문은 `` `${emoji} ${text}` ``다.
기준선: `make test` 81개 통과, 실패 0, skip 0.

**I. 라벨 직렬화 (`nitpick.export`) — 원본 출력과 바이트 단위 비교**
65. [정상·신규·확정] tip이 없는 라벨은 `### 1. (line 3) [❓ Clarify this] Feedback on: "<원문>"` 한 줄만 출력하고 `>` 줄을 붙이지 않는다.
66. [정상·신규·확정] tip이 있는 라벨은 머리 줄 다음에 `> <tip>`을 출력한다.
67. [정상·신규·확정] 파일 묶음 형식에서 라벨이 있는 파일은 항목들 뒤, 다음 파일 섹션이나 `---` 앞에 `### Label Summary`, 빈 줄, `- **🔍 Verify this**: N` 목록을 출력한다.
68. [정상·신규·확정] 요약 목록은 라벨 본문별 개수이고, 문서 순서로 정렬한 항목에서 처음 나온 순서대로 나열한다.
69. [경계·신규·확정] 라벨이 없는 파일에는 `Label Summary`를 출력하지 않는다. 섞여 있으면 라벨이 있는 파일에만 붙는다.
70. [정상·신규·확정] 메시지 형식에서는 `---` 다음에 빈 줄, `## Label Summary`, 목록이 오고, 마지막에 끝 공백 제거(`trimEnd`)를 적용한다.
71. [경계·신규·확정] 라벨도 피드백 개수(`N pieces`), 번호, 문서 순서 정렬에 일반 코멘트와 똑같이 포함된다.
- 회귀: 라벨이 없을 때의 출력은 `tests/test_export.lua`, `tests/test_export_message.lua`가 보호한다.

**J. 라벨 설정 (`setup`, 제안: `nitpick.labels`)**
72. [정상·신규·확정] 기본 라벨은 원본 순서 10개(❓ Clarify this … 👍 Nice approach) 뒤에 👍 Looks good을 더한 11개이고, emoji·text·tip은 원본과 글자 하나까지 같다.
73. [정상·신규·확정] `setup()`을 부르지 않거나 `labels` 없이 불러도 기본 라벨을 쓸 수 있다.
74. [정상·신규·확정] `setup({ labels = {...} })`로 지정하면 기본 목록과 합치지 않고 지정한 목록만 쓴다.
75. [정상·신규·제안] 라벨의 `id`를 생략하면 `text`를 kebab-case로 바꿔 만든다(`Clarify this` → `clarify-this`). 지정한 `id`가 있으면 그것을 쓴다. (원본 `id`와 같은 규칙, 명령 인자와 자동 완성에 쓴다)
76. [경계·신규·확정] `labels = {}`이면 라벨이 없고, `:Nitpick label`은 "라벨이 없습니다" 경고를 띄운다. (결정: 기본 라벨로 되돌리지 않는다)
77. [실패·신규·확정] 라벨 설정에 잘못된 항목이 있으면(`text` 없음, `id` 중복) 그 항목만 빼고 나머지를 쓰며, 뺀 항목을 ERROR로 알린다. `id`가 중복되면 먼저 나온 항목을 남긴다. 알림 문구는 RED에서 정한다.

**K. 라벨 명령 (`:[range]Nitpick label [id]`)**
78. [정상·신규·확정] `:'<,'>Nitpick label clarify-this`는 그 범위에 라벨을 단다. 범위 규칙은 comment와 같다(글자 단위 visual이면 선택한 글자, 범위가 없으면 커서 줄).
79. [정상·신규·확정] `id` 없이 실행하면 `vim.ui.select`에 라벨 목록을 설정 순서대로 `❓ Clarify this` 모양으로 보여 주고, 고른 라벨을 단다.
80. [실패·신규·제안] 고르는 창을 취소하면 아무것도 추가하지 않는다. (사례 37·61과 같은 규칙)
81. [실패·신규·제안] 없는 `id`를 넘기면 추가하지 않고, 쓸 수 있는 `id` 목록과 함께 ERROR 알림을 띄운다. (알 수 없는 하위 명령(`M.run`)과 같은 방식)
82. [정상·변경·확정] 하위 명령 목록과 자동 완성에 `label`이 들어간다. 하위 명령 목록을 고정하는 기존 assertion이 있으면 그것만 고친다(RED에서 확인).
83. [정상·변경·제안] `:Nitpick label ` 다음 인자는 라벨 `id`로 자동 완성된다(`M.complete`). 이전: 하위 명령 다음 인자는 항상 빈 목록 → 이후: `label` 다음에서만 `id`를 완성한다.
84. [정상·신규·확정] `:Nitpick paste` 메시지 버퍼에서도 라벨을 달 수 있고, 메시지 형식(70)으로 복사된다.

**L. 라벨 편집과 삭제**
85. [정상·변경·확정] edit 후보(`comments_at_cursor`)에서 라벨을 뺀다. 이전: 본문(`text`)이 있는 어노테이션은 모두 후보 → 이후: 라벨은 본문이 있어도 빠진다.
86. [실패·신규·확정] 커서 위치에 라벨만 있으면 `:Nitpick edit`은 `nitpick: 커서 위치에 코멘트가 없습니다.` 경고를 띄운다.
87. [정상·신규·확정] 라벨과 코멘트가 겹친 위치에서 `:Nitpick edit`은 고르는 창 없이 코멘트만 고친다.
88. [정상·신규·확정] `:Nitpick remove`의 후보에는 라벨도 들어가고, 라벨을 지울 수 있다.
89. [정상·신규·제안] 고르는 창에서 라벨 항목은 `L3 label: ❓ Clarify this`로 보인다(`describe`). (기존 `L3 comment: 내용` 형식과 맞추고 코멘트와 구분한다)
90. [정상·변경·제안] review 모듈의 `edit_at_cursor`, `text_at_cursor`도 라벨을 건너뛴다. 이전(사례 64): 정렬된 첫 후보 → 이후: 라벨이 아닌 첫 후보. (명령과 모듈 함수의 규칙을 맞춘다)

**M. 라벨 표시**
91. [정상·신규·확정] 라벨 범위에 하이라이트 그룹 `NitpickLabel`이 적용되고, 범위의 끝 줄 아래에 가상 줄 `  ↳ [❓ Clarify this]`(`NitpickLabelText`)가 보인다.
92. [정상·신규·확정] `NitpickLabel`, `NitpickLabelText`도 `default = true`로 정의하고, 사용자 정의가 없으면 각각 `NitpickComment`, `NitpickCommentText`에 연결된다. colorscheme을 바꾼 뒤에도 다시 정의된다. (사례 46과 같은 규칙, 기존 세 그룹은 `tests/test_render.lua` › `하이라이트 그룹`이 보호)
